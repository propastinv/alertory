alertory has been installed.

1. Check the pods are up:
   kubectl --namespace {{ .Release.Namespace }} get pods -l "app.kubernetes.io/instance={{ .Release.Name }}"

2. Point Alertmanager's webhook_configs at:
{{- if .Values.ingress.webhook.enabled }}
   http{{ if .Values.ingress.webhook.tls }}s{{ end }}://{{ .Values.ingress.webhook.host }}{{ .Values.ingress.webhook.path }}
{{- else }}
   kubectl --namespace {{ .Release.Namespace }} port-forward svc/{{ include "alertory.fullname" . }} 8080:{{ .Values.service.port }}
   then http://localhost:8080/api/v1/alerts
{{- end }}

3. Open the admin UI:
{{- if .Values.ingress.ui.enabled }}
   http{{ if .Values.ingress.ui.tls }}s{{ end }}://{{ .Values.ingress.ui.host }}{{ .Values.ingress.ui.path }}
{{- else }}
   kubectl --namespace {{ .Release.Namespace }} port-forward svc/{{ include "alertory.fullname" . }} 8080:{{ .Values.service.port }}
   then http://localhost:8080/ui/
{{- end }}
   (requires OIDC_ISSUER_URL/OIDC_CLIENT_ID/OIDC_CLIENT_SECRET + APP_URL to be set - see values.yaml `secret.data` / `config.APP_URL`,
   otherwise the UI responds 503 by design.)

{{- if not .Values.postgresql.enabled }}

4. This release does NOT bundle Postgres (postgresql.enabled=false). Make sure
   secret.data.DATABASE_URL (or your existingSecret) points at a reachable instance.
{{- end }}
